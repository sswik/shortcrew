# 13. 유튜브 영상 발행 + 연결 인스타 자동 업로드 (구조 설계)

> 상태: **구조 세팅(스캐폴드)**. 실제 배선·최종 n8n JSON 반영은 운영자 확인 후 진행.
> Salog(`n8n-sample/Salog/10-새록-쇼츠발행파이프라인.json`)의 S5 단계를 **참고만** 했으며 코드는 섞지 않았다.

## 목표
렌더 완료된 쇼츠 영상 1개를 **① YouTube 업로드 + ② 연결된 인스타 릴스 자동 업로드** 한다.

## 역할 분담 (핵심)
| 단계 | 담당 | 근거 |
|---|---|---|
| YouTube 업로드 | **n8n `youTube`(OAuth2) 노드** | 채널별 OAuth 크리덴셜은 n8n 이 보유. 서버는 토큰 없음 → 서버 구현 안 함 |
| 영상 공개 URL 확보 | n8n(Drive 업로드+공개권한) 또는 기존 영상 공개직링크 | IG 컨테이너는 공개 URL 필요 |
| **인스타 릴스 발행** | **shortcrew `POST /admin/api/ops/instagram/publish-reel`** (이미 구현) | 컨테이너 생성→인코딩 폴링→발행까지 1콜 |
| 결과 ingest(youtube_id/ig_media_id 시트기록) | n8n → 기존 시트/OPS | 선택 |

## 흐름 (Salog S5 대응 — 참고)
```
렌더영상(공개 직링크)
  ├─ [n8n youTube 노드] YouTube 업로드 → youtube_id
  └─ [n8n httpRequest] shortcrew /instagram/publish-reel
         body: { channel_id, video_url(공개직링크), caption, share_to_feed:true }
         → 서버가 IG 컨테이너 생성·인코딩 폴링·발행 → { media_id, permalink }
  └─ [n8n] 시트에 youtube_id·ig_media_id 기록(선택)
```

## shortcrew 측 (이미 존재 — 추가 구현 불필요)
- `app/admin/ops/routes/instagram_publish.py` → `POST /admin/api/ops/instagram/publish-reel`
  - 인증: `X-Ops-Token: $OPS_API_TOKEN`
  - IG 계정/토큰: `CHANNEL_{id}_IG_ACCOUNT_ID` / `CHANNEL_{id}_IG_ACCESS_TOKEN` (00식 id: 02~37)
  - `dry_run:true` 로 컨테이너 payload 미리보기 가능
- 스텁 경계 명시: `app/admin/ops/services/youtube_ig_bridge.py`

제작·발행이 n8n 밖으로 나갔다. 현재 n8n 활성은 `WFxx-DAILY | OO펌프 …(볼케이노)` 10개뿐이고,
각 워크플로우는 스케줄 → `bash /Users/rodimacbook15/auton8n/volcano-daily/run_daily.sh <slug> --upload`
를 spawn 하고 결과를 디스코드로 알리는 껍데기다. **제작·유튜브 업로드는 Mac 로컬 스크립트가 한다.**

그 결과 IG 가 이중으로 끊겼다.
1. 볼케이노가 `/crosspost/reel` 을 정기 호출하지 않는다(26일간 호출 2건, 9/12 건은 401).
2. 앱 백필도 신규분을 못 집었다 — 구 파이프라인은 시트 상태를 `업로드완료 → 현지화완료` 까지
   진행했지만 볼케이노는 **`업로드완료` 에서 끝난다.** 백필은 `현지화완료` 만 완성으로 봤다.
   여기에 `IG_BACKFILL_ONLY_BEFORE=2026-07-23` 컷이 겹쳐 7/23 이후 영상은 전부 제외됐다.

### IG 처리량을 편성에 맞춤 (2026-09-18)

IG 업로드는 **영상 발행 워크플로우와 분리된 별도 파이프라인**이다(설계 원본
`n8n/WF-과거영상-인스타백필-MASTER.template.json`, 현재 구현은 앱 내부 `ig_backfill_scheduler`).
제작이 n8n → WF500 → 볼케이노로 두 번 이관됐어도 IG 가 살아남은 이유가 이 분리다. 유지한다.

문제는 처리량이었다. **한 슬롯에서 채널당 1건만 올리므로 슬롯 수가 곧 채널별 1일 상한**인데,
슬롯이 5개뿐이라 사이언스(6편/일 생산)를 구조적으로 따라갈 수 없었다.

| 항목 | 이전 | 현재 |
| --- | --- | --- |
| `IG_BACKFILL_SLOTS` | 5개(08:30·10:30·13:30·18:30·23:30) | **8개** 07:40·09:40·11:40·13:40·15:40·17:40·19:40·21:40 |
| `IG_BACKFILL_PER_ACCOUNT` | 5 | **8** |
| `IG_BACKFILL_MIN_AGE_HOURS` | 48 | **6** (당일 영상을 당일 저녁에 따라감) |

이제 5개 편성 채널 전부 생산량 < 상한이라 밀린 물량이 줄어든다(사이언스 6→8, 코리아 5→8,
네이처 4→8, 머니·지오 2→8). IG 계정당 컨텐츠 발행 한도(24시간 50건)에는 한참 못 미친다.

`MIN_AGE_HOURS` 를 6으로 내린 근거는 인라인 크로스포스트가 사라져 이중발행 상대가 없다는 것이다.
**볼케이노가 나중에 `/crosspost/reel` 을 직접 부르기 시작하면 이 값을 다시 올려야 한다** —
시트 `ig_media_id` 는 앱이 쓴 것만 막아주므로 외부 발행과는 충돌할 수 있다.
