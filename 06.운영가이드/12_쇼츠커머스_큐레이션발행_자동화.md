# 12. 쇼츠커머스 큐레이션·자동발행 운영 (전 인플루언서 채널 확장)

> 작성일: 2026-06-13 · 대상: 인플루언서 채널(02 오세련픽·03 왕세림픽·04 한소율픽)의 "쿠팡 큐레이션 → 시트 적재 → 블로그 자동발행 → 인스타 발행" 자동화.
> 설계 배경은 `09_쇼츠커머스브리지설계.md`, 인스타 발행 상세는 `11_인스타자동발행.md` 참고.

## 1. 한눈에
```
[숏크루 내부 큐레이션 스케줄러 19시 KST, n8n 의존 0] → /bridge/curate (채널ID만)
     └ 서버: 채널 분야키워드로 쿠팡검색 → Gemini 주제연관 1개 선정
            → 딥링크(subId=shortcrew) → 채널 시트(탭) 적재(게시중)
            → 블로그(Review) 자동발행(상품 1:1)
[몰] 서버가 시트 직접 읽어 상품 노출 / 블로그·트래킹은 DB

[n8n 웹훅] → /publish-reel (channel_id, fileId, caption)
     └ Drive 공개 → 인스타 릴스 발행
```
- **상품 = 시트(단일 소스)**, 블로그·클릭로그 = DB.
- **채널 무관 동작**: 엔드포인트가 `channel_id`로 채널 설정을 읽어 처리 → 한 벌로 전 채널.

## 2. 엔드포인트
공통 인증: 헤더 `X-Ops-Token: <OPS_API_TOKEN>` (n8n용 공유토큰).

### 2.1 큐레이션 `POST /admin/api/ops/bridge/curate`
```json
{ "channel_id": "02", "dry_run": false, "auto_blog": true }
```
- `topics` 생략 시 → **채널 `trend_keywords`(분야 키워드)를 주제로 자동 사용**(확장 기본).
  특정 영상 주제로 돌리려면 `"topics": ["...", "..."]` 전달.
- `dry_run:true` → 적재·발행 없이 선정 미리보기. `auto_blog:true` → 상품마다 블로그 발행 + 시트 게시상태 `게시중`.
- 코드: `app/admin/ops/routes/bridge.py`.

### 2.2 인스타 발행 `POST /admin/api/ops/instagram/publish-reel`
```json
{ "channel_id": "02", "video_url": "<공개 직링크>", "caption": "..." }
```
- 컨테이너 생성 → 인코딩 폴링 → 발행을 서버가 일괄 처리. 상세: `11_인스타자동발행.md`.

## 3. n8n 워크플로우 (import용, `n8n-sample/`)
> `n8n-sample/`는 gitignore(실제 워크플로우 보관소). Import → 빨간 노드 자격증명 재선택 → 활성화.

### 3.1 큐레이션은 **숏크루 내부 스케줄러**로 이관됨 (n8n 의존 0)
> 현행: 큐레이션은 **숏크루 내부 큐레이션 스케줄러(19시 KST, n8n 의존 0)** 가 채널마다 `/bridge/curate` 를 호출한다. 아래 옛 `WF-인플루언서 큐레이션.json`(n8n) 서술은 이력 참고용.
`(내부 스케줄러 19시 KST) → 채널 목록 → /bridge/curate(채널마다) → 디스코드 알림`
- **큐레이션 대상 채널**: 인플루언서몰 `['02','03','04']`(02 오세련픽·03 왕세림픽·04 한소율픽).
- HTTP 타임아웃 300초. 그날 영상 주제로 돌리려면 대본시트 '제목'을 읽어 `topics`로 넘길 수 있음(선택).
- 끝에 **디스코드 알림**(채널별 적재 상품·블로그 건수).

### 3.2 `WF-쇼츠 IG 크로스포스트.json` (기존 Drive 쇼츠 → IG 일괄)
`스케줄 → 영상시트(시트1) 읽기 → 미발행 필터 → Drive 공개 → /publish-reel → 시트 ig_url 표시 → 디스코드 알림(발행 건별)`
- **용도**: 이미 렌더·유튜브 발행된 쇼츠(영상시트의 `drive_video_id`)를 그 채널 IG로 크로스포스트(확산).
  세련·세림·소율(shortcrew 02/03/04) + 지식쇼츠(short-mall 05/09/10/11/33) 공통.
- **중복방지**: `drive_video_id`·`youtube_url` 있고 `ig_url` 빈칸인 행만 발행 → 발행 후 `ig_url` 기록.
  → **사전 준비: 각 채널 `시트1`에 `ig_url` 컬럼 헤더 1개 추가.**
- **채널별 수정 3곳**: ①`영상시트 읽기`·`시트 표시` 노드 documentId(채널 영상시트) ②필터 코드 `channel_id` ③필터 코드 `base_url`(shortcrew 채널=`shortcrew.co.kr` / 지식쇼츠=`short-mall.com`).
- 영상시트 = 대개 `CHANNEL_xx_FILE_ID` 스프레드시트의 `시트1`(drive_video_id 보유). 단 **홈캠카오스(05)** 는 구조가 달라 해당 n8n 영상 WF의 `시트 읽기` documentId 를 확인해 사용.

> 지식쇼츠 채널 발행은 short-mall 에 동일 `publish-reel` 엔드포인트가 포팅돼 있다(IG 토큰이 short-mall .env). 그래서 `base_url`만 `short-mall.com` 으로 두면 같은 워크플로우로 동작.

## 4. 채널 1개 추가 절차
1. 로스터 모듈 추가: `app/admin/ops/channels/roster/<채널>.py`(golf/safety 참고) → `registry.py`에 등록.
   - `mall_influencer_slug`(=DB 인플루언서 slug), `trend_keywords`(분야 키워드=주제·검색풀) 설정.
2. `.env` 채널 키:
   - 상품 시트: `CHANNEL_{ID}_FILE_ID`(스프레드시트), `CHANNEL_{ID}_TAB`(상품 탭), (선택) `CHANNEL_{ID}_MALL_PRODUCTS_API_URL`(Apps Script. 비우면 서버가 시트 직접 읽음).
   - IG 발행: `CHANNEL_{ID}_IG_USERNAME/ACCOUNT_ID/ACCESS_TOKEN`.
3. 숏크루 내부 큐레이션 스케줄러 **대상 채널 목록에 ID 추가**.
4. (DB) `influencers`에 해당 slug 인플루언서 레코드 존재 확인.

## 5. 시트 구조 (상품 탭, build_rows 스펙)
A(No) B(상품카테고리) C(상품명) D(가격) E(이미지URL) F(쿠팡URL=클린) G(딥링크) H(연관영상No) I(게시상태) J(등록일) K(subId)
- **게시상태 `게시중`만 몰에 노출**(큐레이션 자동발행 시 게시중). F=클린 상품URL(중복제거·추적 안정).

## 6. 추적(딥링크) 주의
- 딥링크 입력은 **반드시 클린 URL(`vp/products/{id}`)** — 이미-제휴 URL을 딥링크하면 subId가 유실됨(검증됨).
- subId 고정 `shortcrew`(시트 K열에도 기록). 공개 랜딩 URL엔 `lptag`만 보이고 subId는 파트너스 리포트에서 집계. (short-mall=shortmall 과 동일 방식)

## 7. 주의
- `OPS_API_TOKEN`·IG 토큰·`google-key.json` 커밋 금지(.env/키파일 전용).
- IG 토큰은 **40일 주기 자동갱신 스케줄러**가 갱신(만료 근절, 수동 교체 불필요). 갱신 실패 시에만 발행 502.
- 큐레이션이 시트에 쓰려면 서비스계정(`sheetbot@sswik-2026`)이 스프레드시트 편집권한 보유(동일 계정이면 공유 불필요).
- 미배포 코드 변경은 도커 재빌드 후 반영.

## 일시중단 (2026-08-18) — 인플루언서 02·03·04 큐레이션·블로그

사용자 요청으로 **상품 큐레이션과 블로그 자동생성을 일시중단**했다. 큐레이션은 두 경로에서 돌기 때문에
스위치도 두 개다.

| 경로 | 주기 | 중단 방법 |
| --- | --- | --- |
| `curation_scheduler` (큐레이션 + `CURATION_AUTO_BLOG` 블로그) | 매일 19시 KST, 02·03·04 | `CURATION_SCHEDULER_ENABLED=0` |
| `scripts_scheduler` 의 **선행 큐레이션** | 매주 월 08시, 02·03 | `SCRIPTS_SCHEDULER_CURATE_ITEMS=0` |

**추가 중단(같은 날)**: 후기→대본 생성도 정지 — `SCRIPTS_SCHEDULER_ENABLED=0`.
이미 시트1 에 쌓인 대본 행은 그대로 남아, 발행 파이프라인이 소진할 때까지 계속 나간다(생성만 멈춤).

재개하려면 `CURATION_SCHEDULER_ENABLED=1` / `SCRIPTS_SCHEDULER_CURATE_ITEMS=12` /
`SCRIPTS_SCHEDULER_ENABLED=1` 로 되돌리고 `docker compose up -d --build shortcrew`.
`.env` 인라인 주석(`KEY=0  # ...`)은 쓰지 말 것 — env_file 은 주석까지 값으로 읽어 숫자 파싱이 깨진다.
