# 11. 지식쇼츠 → 커머스 연결 설계서 (Shorts-Commerce Bridge)

> 작성일: 2026-06-12 · 상태: 설계(Design) · 후속: Phase별 구현
> 목적: 지식쇼츠의 조회수(관심)를 **인플루언서 상품 큐레이션 → 자동DM → 쿠팡 딥링크**로
> 이어지는 구매 동선으로 전환한다. "콘텐츠는 도는데 쇼핑이 끊긴" 문제를 구조로 해결.

---

## 0. 한 줄 요약

기존 `지식쇼츠 자막 → 상품 → 리뷰 발행` 파이프라인은 이미 돌고 있다.
이 설계는 거기에 **(A) 쿠팡 베스트 기반 하이브리드 상품 선택**과
**(B) 지식쇼츠 ↔ 인플루언서 ↔ 인스타 2건 ↔ 자동DM 연결 동선**을 얹는다.
**비즈니스 로직·데이터·DB는 전부 이 프로젝트(FastAPI)가, 외부 SaaS 연결·스케줄·발행 풀칠은 n8n이** 담당한다.

---

## 1. 배경 / 문제 정의

| 현상 | 원인 | 이 설계의 처방 |
|------|------|----------------|
| 유튜브/쇼츠 조회수는 오르는데 구매 전환 0 | 시청자 → 상품 도달 **동선이 없음** | 인스타 교차노출 + 댓글→자동DM→딥링크 |
| short-mall.com / shortcrew.co.kr이 콘텐츠와 단절 | 발행물과 채널이 따로 놂 | 인플루언서를 "덕후 큐레이터"로 두고 양쪽을 한 슬러그로 묶음 |
| 상품이 주제와 따로 놀 위험 | 베스트상품만 뽑으면 연관성↓ | **하이브리드**: 베스트=후보풀, Gemini=주제 연관성 필터 |

핵심 통찰: **가장 약한 고리는 콘텐츠 품질이 아니라 "연결 지점(동선)"과 "전환 트리거(자동DM)"다.**
설계의 무게중심을 거기에 둔다.

## 2. 전체 구조 (End-to-End)

```
                       ┌─────────────────────────── 이 프로젝트(FastAPI/코드) ───────────────────────────┐
                       │                                                                                  │
 [쿠팡 파트너스 API]   │   ① 베스트 수집      ② 하이브리드 큐레이션        ③ 리뷰 생성/발행                │
  bestcategories ──────┼─▶ coupang.fetch_best ─▶ gemini_curator(연관성) ─▶ review_publish_service ─▶ DB   │
  goldbox        ──────┤        │                       ▲                         │                       │
                       │        │                       │ 주제 컨텍스트            ▼                       │
 [지식쇼츠 시트/자막]  │        └───────────────────────┴─ 자막→키워드(기존)   shortcrew.co.kr 몰 노출    │
  plan sheet ──────────┼─▶ shorts_review_pipeline (기존, 매칭/자막/중복방지)                              │
                       │                                                          │                       │
                       │   ④ 딥링크(generate_deeplinks) · ⑤ 클릭추적(ClickLog) · ⑥ DM규칙(DmAutomation) │
                       └──────────────────────────────┬───────────────────────────────────────────────────┘
                                                       │ Webhook / REST (app/webhooks, ops/api_router)
                       ┌───────────────────────────────┴──────────────── n8n (오케스트레이션) ───────────┐
                       │  ⑦ 지식쇼츠 인스타 업로드   ⑧ 인플루언서 상품쇼츠 업로드   ⑨ 교차노출/타이밍     │
                       │  ⑩ 댓글 트리거 → 자동DM 발사(딥링크 포함)   ⑪ 사람 수동 세팅 직전까지 풀칠      │
                       └───────────────────────────────────────────────────────────────────────────────────┘
```

흐름 서사: **지식쇼츠(신뢰 형성) → 연관 인플루언서 상품쇼츠(구매 맥락) → 인스타 양쪽 업로드 → 댓글→자동DM(전환) → 쿠팡 딥링크 → 클릭추적 → 사람 수동 마감.**

## 3. 코드 vs n8n 경계 (가장 중요)

> 원칙: **비즈니스 로직을 n8n 노드 안에 넣지 않는다.** n8n은 "언제·어디로 호출하느냐"만 안다.
> 이 프로젝트는 멱등(idempotent)한 REST/Webhook 엔드포인트를 노출하고, n8n은 그걸 호출만 한다.

| 단계 | 담당 | 근거/위치 |
|------|------|-----------|
| 쿠팡 베스트/골드박스 수집 | **코드** | `coupang.py` 확장 (신규) |
| 하이브리드 상품 선택(주제 연관성) | **코드** | `gemini_curator.py` 활용 |
| 리뷰 글 생성·발행·중복방지 | **코드** | `shorts_review_pipeline.py`, `review_publish_service.py` |
| 딥링크 변환 | **코드** | `coupang.generate_deeplinks` (있음) |
| 클릭 추적 | **코드** | `ClickLog` (있음) |
| DM 규칙 저장/매칭 | **코드** | `DmAutomation`, `app/webhooks/instagram.py` (있음) |
| 인스타 업로드(2건) | **n8n** | IG Graph API / 외부 발행 도구 |
| 업로드 타이밍·교차노출 순서 | **n8n** | 스케줄 + 분기 |
| 댓글→DM 발사 트리거 오케스트레이션 | **n8n → 코드 webhook** | n8n이 감지, 코드가 딥링크 조립·발송 |
| 사람 수동 세팅 | **사람** | 마지막 검수 |

연결 규약: n8n은 **(1) "오늘치 큐레이션 실행" 트리거** → 코드가 리뷰/딥링크/상품 묶음(payload) 반환,
**(2) "발행 완료 콜백"** → 코드가 IG media_id를 `DmAutomation`에 연결. 이 두 개의 엔드포인트가 계약의 핵심.

## 4. 하이브리드 상품 선택 전략 (선택됨)

목표: **"그날 잘 팔리는 것" ∩ "지식쇼츠 주제 연관성"** 을 동시에.

```
1) 후보풀 수집   : 쿠팡 bestcategories(주제 관련 카테고리) + goldbox 당일 N개  (코드: coupang.fetch_best)
2) 주제 컨텍스트 : 당일 지식쇼츠 자막/제목/플랜 키워드                         (코드: 기존 transcript)
3) 연관성 선택   : Gemini가 후보 N개 중 주제와 가장 맞는 1개 + 선정이유          (코드: gemini_curator)
4) 검증/딥링크   : 필터(리뷰>=50, 평점>=4.5) 통과 + generate_deeplinks          (코드: 기존 _apply_filters)
5) 폴백          : 연관 후보 0건이면 기존 "자막→키워드→search" 경로로 강등       (코드: 기존 fallback)
```

설계 포인트
- **후보풀을 먼저 좁힌다**: bestcategories의 categoryId를 지식쇼츠 주제 카테고리에 매핑(설정 테이블). 무관한 베스트가 후보에 안 들어오게.
- **Gemini는 "고르는" 역할만**: 글 생성 전에 1개 선정 + `selection_reason` 반환 → 리뷰 본문 신뢰도/덕후 톤에 재사용.
- **기존 필터 재사용**: `coupang._apply_filters`(리뷰 50 / 평점 4.5)를 후보풀에도 그대로 적용.
- **멱등성**: 같은 (influencer, video_id/날짜)에 대해 재실행해도 중복 발행 안 됨 — 기존 `Review` UniqueConstraint·`source_youtube_video_id` 로직 유지.

## 5. 현재 자산 vs 신규 구현 (Gap 분석)

| 기능 | 상태 | 위치 / 비고 |
|------|------|-------------|
| 쿠팡 HMAC 서명·검색·딥링크 | ✅ 있음 | `coupang.py` |
| 자막→키워드→상품 폴백 | ✅ 있음 | `shorts_review_pipeline.py` |
| 리뷰 생성·발행·중복방지 | ✅ 있음 | `review_publish_service.py`, `Review` |
| Gemini 큐레이터 | ✅ 있음(용도 조정) | `gemini_curator.py` |
| 클릭 추적 | ✅ 있음 | `ClickLog` |
| 댓글→DM 규칙·웹훅 | ✅ 있음 | `DmAutomation`, `app/webhooks/instagram.py` |
| **쿠팡 bestcategories/goldbox 수집** | ❌ 신규 | `coupang.fetch_best_categories`, `fetch_goldbox` |
| **주제↔카테고리 매핑 설정** | ❌ 신규 | 채널 config 또는 신규 테이블 |
| **하이브리드 선택기** | ⚠️ 부분 | `gemini_curator`에 "후보 N→1 선정" 함수 추가 |
| **n8n 연동 엔드포인트(트리거/콜백)** | ⚠️ 부분 | `ops/api_router`에 2개 추가 |
| **인스타 업로드 2건 + 교차노출** | ❌ n8n | n8n 워크플로우 |
| **DM에 당일 딥링크 자동 주입** | ⚠️ 부분 | `DmAutomation.dm_link`를 당일 상품으로 갱신하는 코드 |

## 6. 데이터 모델 변경 제안 (최소)

기존 모델을 최대한 재사용. 추가는 작게.

- `Review`에 `selection_reason: Text|null` (덕후 톤/신뢰 근거 재사용) — 선택.
- (선택) `BestPick` 신규 테이블: 당일 베스트 수집·선정 이력 1행/일.
  - `date, channel_id, category_id, candidate_json, picked_product_id, selection_reason, deep_link`
  - 목적: 재실행 멱등성 + 운영 가시성(어제 뭐 골랐나). 없어도 동작은 가능(로그로 대체).
- `DmAutomation.dm_link`: 이미 존재 → **당일 선정 딥링크로 갱신하는 잡** 추가로 해결(스키마 변경 불필요).

> 스키마는 MySQL(`crews`)에서 `create_all` 로 생성. 컬럼 추가는 가산형으로만(파괴적 변경 금지).

## 7. 인터페이스 계약 (코드 ↔ n8n)

신규 엔드포인트 2개 (위치: `app/admin/ops/api_router.py` 또는 `app/webhooks`)

1. `POST /ops/bridge/run-daily`  (n8n 스케줄 → 코드)
   - in: `{ channel_id, date? , dry_run? }`
   - 동작: 베스트 수집 → 하이브리드 선택 → 리뷰 발행 → 딥링크 → DM 링크 갱신
   - out: `{ review_id, product, deep_link, influencer_slug, mall_url, selection_reason, shorts_caption_hint }`
   - 멱등: 같은 (channel, date) 재호출 시 기존 결과 반환.

2. `POST /ops/bridge/publish-callback`  (n8n 발행 후 → 코드)
   - in: `{ channel_id, review_id, ig_media_id, permalink, kind: "knowledge"|"shopping" }`
   - 동작: `DmAutomation.ig_media_id`/`media_permalink` 연결(타깃 `next` 모드 baseline 갱신)
   - out: `{ ok, dm_automation_id }`

> 인증: 기존 백오피스 인증/시크릿 헤더 재사용. n8n에는 단일 토큰만 노출.

## 8. 단계별 로드맵 (Phase)

| Phase | 산출물 | 의존 | 핵심 검증 |
|-------|--------|------|-----------|
| **P1. 베스트 수집** | `coupang.fetch_best_categories`, `fetch_goldbox` + 단위테스트 | 없음 | 실제 API 1회 호출, 필터 통과 N건 |
| **P2. 하이브리드 선택기** | `gemini_curator` "후보→1 선정" + `selection_reason` | P1, 자막 | 주제와 무관 후보를 떨어뜨리는지 |
| **P3. 일일 실행 엔드포인트** | `POST /ops/bridge/run-daily` (dry_run 우선) | P1,P2,기존 발행 | dry-run 로그로 end-to-end 1건 |
| **P4. DM 링크 자동 갱신** | 당일 딥링크 → `DmAutomation.dm_link` | P3 | 댓글→DM에 당일 링크 나가는지 |
| **P5. n8n 워크플로우** | 인스타 2건 업로드·교차노출·콜백 | P3,P4 | 수동 트리거로 1사이클 |
| **P6. 스케줄·운영** | 골드박스 07:30 이후 크론, 모니터링 | 전부 | 무인 1일 운영 |

각 Phase는 **dry-run/로그 우선 → 실발행**. 기존 파이프라인의 `dry_run` 패턴을 그대로 계승.

## 9. 리스크 / 열린 결정

| 항목 | 리스크 | 메모 |
|------|--------|------|
| 쿠팡 API limit | search에서 "limit out of range" 이력 → best도 보수적 호출 | `coupang.py` 주석 참고 |
| 골드박스 갱신 시각 | 매일 07:30 업데이트 → 그 전 실행 시 전일자 | 크론 07:40+ 권장 |
| 인스타 업로드 도구 | IG Graph 직접 vs 외부 발행 SaaS | **결정 필요** |
| 주제↔카테고리 매핑 | 수작업 매핑 vs 자동 추론 | 초기엔 채널별 수동 매핑 권장 |
| DM 정책 | 메타 자동화 정책/팔로워 한정 옵션 | `DmAutomation.follower_only` 기존 |
