# 15. 인스타 일일 운영 리포트 (디스코드)

매일 20:30(KST) 인스타 전 채널의 24시간 성과·발행 현황을 디스코드(숏크루 서버)로 자동 발송한다.
유튜브 쪽 `WF-OPS 일일 운영 리포트`(n8n)의 인스타 버전이되, **n8n 이 아니라 앱 내부 스케줄러**가 담당한다.

## 왜 n8n 이 아니라 앱인가

IG 장기 액세스 토큰은 60일 만료이고, 유효 토큰은 앱의 자동갱신 저장소(`/app/logs/ig_tokens.json`,
가이드 13·`ig_token_refresh`)에만 최신본이 있다. n8n 노드에 토큰을 하드코딩하면 60일 뒤 또 만료로
죽는다. 리포트는 `current_token(channel_id)` 으로 항상 갱신본을 읽는다.

## 구성

| 구분 | 위치 |
| --- | --- |
| 스케줄러·집계 | `app/admin/ops/services/ig_report_scheduler.py` |
| 수동 실행 API | `app/admin/ops/routes/ig_report.py` (`/admin/ops/ig-report/...`) |
| 기동 | `main.py` startup `_startup_ig_report_scheduler` |
| 전송 | `discord_notify.notify(..., env_key=IG_REPORT_WEBHOOK_ENV)` — 운영값 `DISCORD_WEBHOOK_IG_REPORT`(리포트 전용 채널) |

## 리포트 내용

1. **전체 요약** — 팔로워 합계(전일 대비 증감) / 24h 조회·도달·상호작용 / 24h 발행 릴스 수 / 채널 수
2. **채널별 1줄** — 조회수 내림차순. 팔로워(증감)·조회·도달·반응·발행 건수
3. **점검 필요** — 24h 발행 0건 채널, 계정/지표 조회 실패 채널, 토큰 만료 D-14 이내 채널
4. **상위 릴스 TOP N** — 24h 발행분 중 조회수 상위(퍼머링크 포함)

지표 출처는 Graph API 뿐이라 **크로스포스트(n8n)든 백필(앱)이든 경로와 무관하게 실제 업로드된 것만** 잡힌다.

- 계정: `GET /{ig_id}?fields=username,followers_count,media_count`
- 계정 인사이트: `GET /{ig_id}/insights?metric=views,reach,total_interactions&period=day&metric_type=total_value`
- 미디어: `GET /{ig_id}/media?fields=id,timestamp,permalink,media_product_type,like_count,comments_count&limit=25`
- 릴스 조회수: `GET /{media_id}/insights?metric=views`

디스코드 2000자 한도에 맞춰 1900자에서 자르며, **채널 목록부터 생략**한다(점검·상위릴스가 우선).

## 팔로워 증감 기준선

실제 발송(dry_run 아님) 때마다 채널별 팔로워 수를 `IG_REPORT_STATE_FILE` 에 스냅샷한다.
다음 날 리포트가 이 값과 비교해 증감을 낸다. **첫 실행은 기준선이 없어 증감 표기를 생략**한다.

## env

| 키 | 기본값 | 설명 |
| --- | --- | --- |
| `IG_REPORT_ENABLED` | (꺼짐) | `1` 이면 스케줄러 기동 |
| `IG_REPORT_AT` | `20:30` | 발송 시각(KST) |
| `IG_REPORT_CHANNELS` | 전 채널 | 공백/쉼표 구분 채널 id. 미지정 시 `CHANNEL_xx_IG_ACCOUNT_ID` 가 있는 전 채널 |
| `IG_REPORT_WEBHOOK_ENV` | `DISCORD_WEBHOOK_IG` | 웹훅 URL 을 읽을 env 키(채널 분리용). 운영은 `DISCORD_WEBHOOK_IG_REPORT` 사용 |
| `IG_REPORT_TOP_N` | `3` | 상위 릴스 표시 개수 |
| `IG_REPORT_STATE_FILE` | `/app/logs/ig_report_state.json` | 팔로워 스냅샷 |
| `IG_GRAPH_VERSION` | `v23.0` | Graph API 버전 |

## 수동 실행

인증 헤더 `X-Ops-Token: $OPS_API_TOKEN`.

```bash
# 대상 채널·발송 시각 확인
curl -s -H "X-Ops-Token: $OPS_API_TOKEN" http://127.0.0.1:8028/admin/ops/ig-report/status

# 미리보기(디스코드 전송 안 함) — 기본값이 dry_run
curl -s -X POST -H "X-Ops-Token: $OPS_API_TOKEN" -H 'Content-Type: application/json' \
  -d '{"dry_run": true}' http://127.0.0.1:8028/admin/ops/ig-report/run-now

# 실제 전송
curl -s -X POST -H "X-Ops-Token: $OPS_API_TOKEN" -H 'Content-Type: application/json' \
  -d '{"dry_run": false}' http://127.0.0.1:8028/admin/ops/ig-report/run-now
```

## 문제 대응

- **특정 채널만 "조회 실패"** — 토큰 만료 또는 계정 ID 오설정. 가이드 13의 토큰 갱신 절차 확인.
- **전 채널 발행 0건** — IG 발행 경로(n8n 크로스포스트 / 앱 백필) 자체가 멈춘 것. n8n OPS 리포트와 대조.
- **리포트가 아예 안 옴** — `IG_REPORT_ENABLED=1` 여부, 컨테이너 로그의 `ig_report started` 라인 확인.
  `.env` 를 고쳤다면 `docker compose restart` 로는 반영되지 않는다(env_file 은 생성 시 고정).
  `docker compose up -d --build shortcrew` 로 재생성할 것.
- 리포트 실패는 로그만 남기고 루프를 유지한다(앱·다른 스케줄러에 영향 없음).
