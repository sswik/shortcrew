## 1. 운영 모델 — "콘텐츠 브랜드 ↔ 인플루언서 몰" 세트
쇼츠 콘텐츠(조회수)와 인플루언서 몰(전환)을 한 세트로 묶고, 같은 코드/워크플로우로 전 채널에 복제한다.

| 콘텐츠 브랜드(지식쇼츠) | 인플루언서/몰 | 백엔드 | 공개 |
|---|---|---|---|
| 홈캠카오스 `homecam.chaos` (보안) | 안지아픽 `jia.safety` | 홈캠=short-mall / 안지아=short-crew | shortcrew.co.kr/safety |
| (확장) 히스토리·사이언스·스페이스·필로소피 등 | (확장) 세련골프·세림테니스·한소율픽 등 | 각 프로젝트 | — |

- 원칙: short-mall 콘텐츠 → short-mall IG, short-crew 콘텐츠 → short-crew IG.
- **상품 = 시트(단일 소스)**, 블로그·클릭로그 = DB. 큐레이션 상품은 인플루언서 몰에 적재.

## 2. 전체 프로세스 A~Z

```
[A 대본]  n8n WF-AUTO-SCRIPT — 채널 분야 주제 30개 생성(시트1)
   │
[B 영상]  n8n 채널별 영상 WF — TTS→Remotion 렌더→Drive 저장→YouTube 업로드
   │            (drive_video_id 가 영상시트에 기록됨)
   ├─────────────► [C SNS 확산]  n8n WF-쇼츠 IG 크로스포스트
   │                 → 영상시트 미발행분 → Drive 공개 → /publish-reel → 채널 IG 릴스
   │                 (세련·세림·안지아·지식쇼츠 공통)
   │
[D 큐레이션]  n8n WF-인플루언서 큐레이션 → /bridge/curate (채널ID만)
   │   서버: 분야키워드(or 영상주제)로 쿠팡검색 → Gemini 주제연관 1개 선정
   │        → 딥링크(클린URL, subId=shortcrew) → 채널 시트(탭)에 적재(게시중)
   │
[E 블로그]  auto_blog → 상품 1:1 리뷰(Review) 자동발행(DB) → 몰 '포스트' 탭
   │
[F 몰 노출]  서버가 채널 시트를 직접 읽어 '상품' 탭 노출(게시중만)
   │
[G 전환]  영상 고정댓글/DM → 몰(/safety 등) → 상품·블로그 → 쿠팡 딥링크 구매
   │   (등록 상품으로 관리자가 자동DM 규칙 수동 세팅)
   │
[H 추적]  ClickLog(DB) + subId=shortcrew(파트너스 리포트) 로 콘텐츠→클릭→구매 측정
```

## 3. n8n 워크플로우 (확장형, `n8n-sample/`)
2개를 운영한다(대본·영상 생성은 기존 WF). **1개는 커머스(상품·블로그) 생성, 1개는 기존 쇼츠를 IG로 확산.** 비즈니스 로직은 전부 FastAPI 엔드포인트에 있고, n8n 은 스케줄·호출·풀칠만 담당한다(CLAUDE.md 원칙).

### 3.1 `WF-인플루언서 큐레이션.json` — 상품·블로그 생성(커머스)
- **목적**: 채널 분야에 맞는 쿠팡 상품을 골라 몰에 채우고, 그 상품으로 블로그 글까지 자동 발행. **매출 동선(몰·블로그)을 채우는** 워크플로우(IG 발행 아님).
- **트리거**: 스케줄(예: 매월 6일 또는 매일).
- **흐름**: `스케줄 → 채널 목록(Code) → 채널마다 POST /bridge/curate`
  → 서버가 분야 키워드(or 영상 주제)로 쿠팡 검색 → Gemini 가 주제 연관 상품 1개 선정 → 딥링크(클린URL, subId=shortcrew) → **채널 시트에 적재(게시중)** + **상품 1:1 블로그(Review) 자동 발행**.
- **결과**: 공개 몰의 '상품' 탭 + '포스트' 탭이 채워짐.
- **확장**: Code 노드의 `const channels = ['105']` 에 **채널 ID만 추가**하면 그 채널도 자동 큐레이션.

### 3.2 `WF-쇼츠 IG 크로스포스트.json` — 기존 쇼츠를 IG에 일괄 확산(주력 자동화)
- **목적**: 이미 렌더·유튜브 발행되어 **Drive에 쌓인 쇼츠들을 그 채널 IG로 자동 발행**(SNS 도달 확산). 여러 건을 한 번에, 중복 없이.
- **트리거**: 스케줄.
- **흐름**: `스케줄 → 영상시트(시트1) 읽기 → 미발행 필터 → Drive 공개 → POST /publish-reel → 시트에 ig_url 기록`
  - 미발행 필터 = `drive_video_id` 있고 `youtube_url` 있고 **`ig_url` 빈칸**인 행만 → 발행 후 `ig_url` 기록 → 다음 실행 때 건너뜀(중복 방지).
- **결과**: 채널별 기존 쇼츠가 해당 IG 계정에 릴스로 게시. 세련·세림 + 지식쇼츠(05/09/10/11/33) 전부 이걸로.
- **확장**: 복사 후 3곳만 변경 — ①시트 읽기/표시 노드의 documentId(채널 영상시트) ②필터 코드 `channel_id` ③`base_url`(shortcrew 채널=`shortcrew.co.kr` / 지식쇼츠=`short-mall.com`).
- **사전 준비**: 각 채널 `시트1`에 `ig_url` 컬럼 헤더 1개 추가(중복 방지 표시용).

### 한눈에 비교
| 워크플로우 | 무엇 | 트리거 | 발행 단위 | 호출 엔드포인트 |
|---|---|---|---|---|
| 큐레이션 | 상품·블로그(커머스) | 스케줄 | 채널별 일괄 | `/bridge/curate` |
| 쇼츠 IG 크로스포스트 | 기존 쇼츠 → IG | 스케줄 | 시트 배치(중복방지) | `/instagram/publish-reel` |

> 운영 = **큐레이션(커머스 채우기) + 쇼츠 IG 크로스포스트(쇼츠 확산)** 2개. (단건 웹훅 발행 WF는 크로스포스트와 기능이 겹쳐 제거함 — `publish-reel` 엔드포인트 자체는 두 WF가 공용.)

운영가이드 상세: `06.운영가이드/11_인스타자동발행.md`, `12_쇼츠커머스_큐레이션발행_자동화.md`.

## 4. 채널 1개 추가 = 설정 몇 줄

→ 같은 엔드포인트·워크플로우가 그대로 처리(코드 변경 0).

## 5. 정합성·추적 (검증된 핵심)
- **딥링크 subId**: 입력을 **클린 URL(`vp/products/{id}`)** 로 정규화해야 `subid=shortcrew` 전파(이미-제휴 URL은 유실). short-mall(`shortmall`)과 동일 방식. 시트 K열에도 subId 기록. → 실측으로 랜딩 URL `subid=shortcrew` 확인.
- **상품 단일 소스 = 시트**: 큐레이션이 시트에 적재, 몰은 시트를 읽음(서버 직접 읽기 또는 Apps Script). 블로그·트래킹만 DB.
- **공개 정책**: 공개 링크는 `lptag`만 노출, subId 는 파트너스 추적값(정책 준수).

## 6. 기대 효과 (KPI 관점)
- **도달 확대**: 영상 1편당 발행 채널 1→2~3개(유튜브 + IG×세트). 잠자던 채널 IG 자산화.
- **전환 동선 생성**: 빈 몰 → 영상주제 연관 상품 + 블로그 + DM으로 "콘텐츠→구매" 경로 완성("도는데 안 사던" 문제 해소).
- **운영 효율**: 큐레이션·블로그·발행 자동화로 **채널 추가의 한계비용↓** — 세트 복제로 분야 확장(보안→골프→테니스→지식 전반).
- **측정 가능**: ClickLog + 딥링크 subId 로 채널·콘텐츠별 클릭/전환 집계 → 잘 되는 세트에 자원 집중.
- **콘텐츠 자산 재활용**: 이미 만든 수천 개 쇼츠를 크로스포스트로 재발행(추가 제작비 0).

## 7. 남은 운영 액션 (코드는 완료)
- n8n: 3개 워크플로우 Import → 자격증명 연결 → 채널값 설정 → 활성화.
- 각 채널 영상시트(`시트1`)에 **`ig_url` 컬럼 추가**(크로스포스트 중복방지용).
- 발행 후 **고정댓글/DM에 몰 링크** + 자동DM 키워드 규칙 세팅.
- (선택) 골프·테니스를 상품쇼츠 발행 구조로 전환(선생님과) 후 큐레이션 합류.
- 보안: `.env` `GITHUB_TOKEN` 폐기 권장 / IG 토큰 만료(60일) 시 교체.
