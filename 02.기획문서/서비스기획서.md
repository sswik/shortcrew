# 서비스 기획서

> shortcrew 서비스 컨셉·운영 모델. (운영 코드/문서 기반)

## 한 줄 정의

인플루언서의 채널 트래픽을 **슬러그 기반 독립몰+리뷰 허브**로 받아, 상품은 시트로·리뷰는 수동/AI로 생산해 쿠팡 파트너스 전환을 극대화하는 운영 플랫폼.

## 문제 정의

- 인플루언서마다 사이트를 만들면 유지보수가 폭증한다.
- 리뷰 콘텐츠를 사람이 매번 작성하면 발행 속도가 느리다.
- 쇼츠를 올릴 때마다 대응 리뷰를 수동으로 맞추기 어렵다.

## 해결 방식

| 문제 | 해결 |
|------|------|
| 사이트 난립 | 슬러그 라우팅으로 1서버 N허브 |
| 상품 갱신=배포 | 상품 진실 소스를 시트로 분리 |
| 리뷰 생산 부담 | 백오피스 에디터 + **AI 리뷰 초안** |
| 쇼츠-리뷰 동기화 | ~~쇼츠 계획 시트 트리거 → 리뷰 자동 발행(일일 크론)~~ **(폐기)** → 현행: 숏크루 내부 큐레이션 스케줄러 + 유튜브/IG 크로스포스트 |
| 댓글 응대 누락 | 인스타 댓글→자동 답글+DM(두-ID 안전) |
| 전환 불투명 | `/api/click` + 클릭 집계 |

## 사용자 여정

```
[인플루언서 쇼츠/영상] → 프로필/댓글 링크
   → /{slug} 독립몰 허브 (상품·리뷰·소개 탭)
   → 리뷰 열람 → 연결 상품 클릭(/api/click) → 쿠팡 전환
(폐기) 쇼츠 발행 계획 시트 → 06:00 크론 → 리뷰 자동 발행
(자동) 숏크루 내부 큐레이션 스케줄러(Gemini 상품 큐레이션, 19시 KST) → 유튜브/IG 크로스포스트
(병행) 인스타 댓글 → 공개 답글 + DM(딥링크+몰링크)
```

## 운영 모델

- **채널 추가**: 로스터 코드(`roster/*.py`) + `CHANNEL_NN_*` env. (00식 34채널: 02 오세련픽/golf·03 왕세림픽/tennis·04 한소율픽/shopping = 인플루언서몰, 05~37 지식펌프. ~~쇼츠 자동화 `SHORTS_*` 키~~ 폐기.)
- **상품**: 쿠팡 검색 → 시트 전송 → 공개 몰 반영(120s 캐시).
- **리뷰**: 수동(Toast UI) / AI 초안 2경로. (쇼츠 시트 자동 발행 경로는 폐기)
- **DM**: 채널별 규칙, 두-ID 하드닝.
- **분석**: 클릭 요약 + 접속 로그.

## 제품 경계

- shortcrew = **인플루언서 계열**. 지식채널 계열은 자매 제품 **short-mall**. 인스타 댓글→DM은 각 **별도 Meta 앱**. ([[project_products_and_ig_apps]])

## 확장 여지(코드 근거 없는 제안)

- 리뷰 성과(조회·클릭) 대시보드, 인플루언서몰 퍼널(큐레이션→크로스포스트→DM) 성과 실측. (MySQL 전환·SQLite 폐기는 완료)
